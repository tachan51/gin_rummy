# AI のしくみ（最強レベル）

実装: [`web/js/ai.js`](../web/js/ai.js)（ルール計算は [`web/js/engine.js`](../web/js/engine.js)）

「最強」AIは、探索木を深く読むのではなく、**情報の推定**と**1手先の期待値計算**を組み合わせたヒューリスティック型です。パラメータは自己対戦で調整しました（経緯は [history.md](history.md)）。

## 0. 基本計算：最適メルドとデッドウッド

- 手札からメルド（同じ数字3〜4枚のセット、同スート3枚以上連続のラン）の候補をすべて列挙し、互いに重ならない組み合わせを深さ優先で全探索して、カバーできる点数の最大値を求めます。デッドウッド = 手札合計 − その最大値。
- 手札内のカードをビットマスクで表し、型付き配列を使い回すことで、1回の計算をマイクロ秒単位に抑えています。AIはこの計算を1手で数千回呼びます。
- `discardDeadwoods`：11枚の手札について、「どの1枚を捨てると残りのデッドウッドがいくつになるか」を1回の列挙でまとめて求めます。
- 付け札（レイオフ）：ノックされた側のメルド候補に「ノック側のランの両端を伸ばすカード列」「3枚セットの4枚目」を加えて同じ探索をし、付け札込みで最適な結果を出します。ノック側は、デッドウッドが最小になる組み方のうち、相手のデッドウッドが最も多く残る組み方を選びます。

## 1. カードカウンティングと相手手札の推定（`analyze`）

公開情報（捨て札の山、各プレイヤーの行動履歴）から、カード52枚を次の4つに分類します。

| 状態 | 内容 |
| --- | --- |
| 自分の手札 | 確定 |
| 死に札 | 現在の捨て札の山にあるカード |
| 相手が持っていると確定 | 相手が捨て札から拾い、まだ捨てていないカード |
| 未知 | 山札か相手の手札のどちらか |

未知カードそれぞれについて「相手が持っている確率」`pOpp` を推定します。

- 基本は「相手手札の未知枚数 ÷ 未知カード総数」。
- 相手が**拾った**カードの同じ数字（×1.7）・同スート隣（×1.6）・2つ隣（×1.25）は、持っている可能性を上げます。
- 相手が**捨てた／見送った**カード（表札のパス、山札を引いたときの捨て札の一番上）の周辺は、同様に可能性を下げます（×0.65 / 0.7 / 0.88）。
- 山札から次に引く確率 `pDraw` は (1 − `pOpp`) を正規化したものです。

## 2. 手札の評価（`evalHand`）

10枚の手札の評価値（小さいほど良い）:

```
評価 = デッドウッド − α × Σ_c pDraw(c) × 改善量(c)
改善量(c) = max(0, 今のデッドウッド − c を引いて最善の1枚を捨てた後のデッドウッド)
           （ジン到達なら +ginBonus、ノック圏(10以下)に初めて入るなら +knockBonus）
```

- 第2項は「次に山札から1枚引いたときに、手がどれだけ良くなるかの期待値」で、待ち（アウツ）の多さとその価値を表します。
- 山札が残り少ないほど将来のドローに価値がないので、α は山札枚数に応じて減らします（`alphaDecayStock` 枚未満で線形に減少）。

## 3. 捨て札の危険度（`danger`）

カード d を捨てたとき、相手がそれでメルドを作れる確率です。

- セット：同じ数字の他3枚のうち2枚以上を相手が持つ確率
- ラン：(d−2, d−1)、(d−1, d+1)、(d+1, d+2) のいずれかの組を相手が持つ確率
- 確定カードは確率1、死に札・自分の札は0として計算します。

## 4. 捨てるカードの決定

捨てられる各カードについて `評価(残り10枚) + β × 危険度` を計算し、最小のものを捨てます。

## 5. 引く場所の決定（山札 or 捨て札）

1手先の期待値で比較します。

- **捨て札を取る**：取った後の11枚で、最善の捨て札を選んだときのスコア。
- **山札を引く**：未知カード c すべてについて「c を引いて最善の捨て札を選んだときのスコア」を `pDraw(c)` で重み付き平均したもの（計算量を抑えるため、各 c ではデッドウッド上位4候補だけを詳しく評価）。

小さい方を選びます。最初の表札の判断も同じ方法です（パス ≒ 山札）。

## 6. ノック判断（`shouldKnock` / `knockStats`）

デッドウッド10以下になれる場合、すぐノックするかどうかを決めます。

1. **相手手札のサンプリング**：確定カード＋未知カードから `pOpp` で重み付けして10枚を作ります。さらに、相手がこれまで引いた回数ぶん「山札から1枚引いてデッドウッド最小になるように捨てる」をシミュレーションし、ゲームの進行に応じて上達した手札にします（完全ランダムな手札では相手のデッドウッドを過大評価してしまうため）。
2. 60通りのサンプルについて、付け札込みで相手のデッドウッドを計算し、**アンダーカットされる確率**と**期待得点**を求めます。
3. アンダーカット確率 ≤ 18% かつ期待得点 ≥ 0 ならノック。山札が残り8枚以下ならノックを優先します（期待得点 > −5 でノック）。デッドウッド0（ジン）なら必ずノックします。

## 7. 他のレベル

- **ふつう**：デッドウッド最小化だけを見る貪欲AI。捨て札で2点以上良くなるなら取り、デッドウッドが最小になる札を捨て、ノックできればすぐノックします。
- **よわい**：「ふつう」に35%の確率でランダムな判断を混ぜたもの。

## 主なパラメータ（`DEFAULT_PARAMS`）

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `alpha` | 1.2 | ドローによる改善期待値の重み |
| `alphaDecayStock` | 25 | 山札がこの枚数より少なくなると α を減らす |
| `knockBonus` / `ginBonus` | 4 / 8 | ノック圏到達・ジン到達ドローへのボーナス |
| `beta` | 4 | 危険度ペナルティの重み |
| `topK` | 4 | 仮想ドロー後に詳しく評価する捨て札候補数 |
| `samples` | 60 | ノック判断のサンプル数 |
| `undercutMax` | 0.18 | 許容するアンダーカット確率 |
| `lateStock` | 8 | この枚数以下の山札ではノックを優先 |
| `deepK` | 0 | 捨て札の2手読み（試したが効果なしのため無効） |

## 計算時間

1手あたり平均約1〜2ms、最大でも60ms程度（Node.js 22 で計測）。ブラウザのメインスレッドで動かしても操作に支障はありません。
