# AI のしくみ（最強レベル）

実装: [`web/js/ai.js`](../web/js/ai.js)（ルール計算は [`web/js/engine.js`](../web/js/engine.js)）

「最強」AI（v2）は2層構成です。

- **ヒューリスティック層**（1〜6章）：情報の推定と1手先の期待値計算で、候補手を絞り込み、手札の良さを数値化します。初版（v1）はこの層だけで動いていました。
- **探索層**（7章）：相手の手札と山札の並びを何百通りも仮定し、相手の次の手番までシミュレーションして、**自己対戦から学習した局面評価**で候補手を比べます。

経緯と測定結果は [history.md](history.md) にあります。

## 0. 基本計算：最適メルドとデッドウッド

- 手札からメルド（同じ数字3〜4枚のセット、同スート3枚以上連続のラン）の候補をすべて列挙し、互いに重ならない組み合わせを深さ優先で全探索して、カバーできる点数の最大値を求めます。デッドウッド = 手札合計 − その最大値。
- 手札内のカードをビットマスクで表し、型付き配列を使い回すことで、1回の計算をマイクロ秒単位に抑えています。AIはこの計算を1手で数千回呼びます。
- `discardDeadwoods`：11枚の手札について、「どの1枚を捨てると残りのデッドウッドがいくつになるか」を1回の列挙でまとめて求めます。
- 付け札（レイオフ）：ノックされた側のメルド候補に「ノック側のランの両端を伸ばすカード列」「3枚セットの4枚目」を加えて同じ探索をし、付け札込みで最適な結果を出します。ノック側は、デッドウッドが最小になる組み方のうち、相手のデッドウッドが最も多く残る組み方を選びます。

## 1. カードカウンティングと相手手札の推定（`analyze`）

公開情報（捨て札の山、各プレイヤーの行動履歴）から、カード52枚を次の4つに分類します。

| 状態 | 内容 |
| --- | --- |
| 自分の手札 | 確定 |
| 死に札 | 現在の捨て札の山にあるカード |
| 相手が持っていると確定 | 相手が捨て札から拾い、まだ捨てていないカード |
| 未知 | 山札か相手の手札のどちらか |

未知カードそれぞれについて「相手が持っている確率」`pOpp` を推定します。

- 基本は「相手手札の未知枚数 ÷ 未知カード総数」。
- 相手が**拾った**カードの同じ数字（×1.7）・同スート隣（×1.6）・2つ隣（×1.25）は、持っている可能性を上げます。
- 相手が**捨てた／見送った**カード（表札のパス、山札を引いたときの捨て札の一番上）の周辺は、同様に可能性を下げます（×0.65 / 0.7 / 0.88）。
- 山札から次に引く確率 `pDraw` は (1 − `pOpp`) を正規化したものです。

### 1.1 学習した推定モデル（最強で使用。`oppModel: 1`）

上の倍率は手で決めた値です。最強では代わりに、自己対戦で集めたデータからロジスティック回帰で学習したモデル（`web/js/opp-model.js`）を使います。

- 各未知カードについて19個の特徴量（`oppCardFeatures`）を計算します。主なものは次のとおりです。
  - 相手が拾って持っている札・捨てた札・見送った札との関係（同じ数字か、同じスートの1つ隣・2つ隣か）
  - そのカードとメルドを組める札がまだ場に残っているか
  - カードの点数、相手の手番数
- 確率は `sigmoid(logit(U/未知枚数) + 重み・特徴量)` で求め、未知カードの確率の合計が相手手札の未知枚数 U になるよう補正します。
- 学習データは `tools/opp_eval.mjs`、当てはめは `tools/fit_opp.py` で作ります。最強同士の対局から集めた約78万枚分のデータです。

## 2. 手札の評価（`evalHand`）

10枚の手札の評価値（小さいほど良い）:

```
評価 = デッドウッド − α × Σ_c pDraw(c) × 改善量(c)
改善量(c) = max(0, 今のデッドウッド − c を引いて最善の1枚を捨てた後のデッドウッド)
           （ジン到達なら +ginBonus、ノック圏(10以下)に初めて入るなら +knockBonus）
```

- 第2項は「次に山札から1枚引いたときに、手がどれだけ良くなるかの期待値」で、待ち（アウツ）の多さとその価値を表します。
- 山札が残り少ないほど将来のドローに価値がないので、α は山札枚数に応じて減らします（`alphaDecayStock` 枚未満で線形に減少）。

## 3. 捨て札の危険度（`danger`）

カード d を捨てたとき、相手がそれでメルドを作れる確率です。

- セット：同じ数字の他3枚のうち2枚以上を相手が持つ確率
- ラン：(d−2, d−1)、(d−1, d+1)、(d+1, d+2) のいずれかの組を相手が持つ確率
- 確定カードは確率1、死に札・自分の札は0として計算します。

## 4. 捨てるカードの決定（v2では探索の候補を絞るのに使用）

捨てられる各カードについて `評価(残り10枚) + β × 危険度` を計算し、最小のものを捨てます。

## 5. 引く場所の決定（山札 or 捨て札。v2では探索なしのときのみ）

1手先の期待値で比較します。

- **捨て札を取る**：取った後の11枚で、最善の捨て札を選んだときのスコア。
- **山札を引く**：未知カード c すべてについて「c を引いて最善の捨て札を選んだときのスコア」を `pDraw(c)` で重み付き平均したもの（計算量を抑えるため、各 c ではデッドウッド上位4候補だけを詳しく評価）。

小さい方を選びます。最初の表札の判断も同じ方法です（パス ≒ 山札）。

## 6. ノック判断（`knockStats`）

デッドウッド10以下になれる場合の判断材料です（v2 では探索層がこの結果を使って最終判断します。7章）。

1. **相手手札のサンプリング**：確定カード＋未知カードから `pOpp` で重み付けして10枚を作ります。さらに、相手がこれまで引いた回数ぶん「山札から1枚引いてデッドウッド最小になるように捨てる」をシミュレーションし、ゲームの進行に応じて上達した手札にします（完全ランダムな手札では相手のデッドウッドを過大評価してしまうため）。
2. 各サンプルについて、実際の得点計算（ノック側は相手の付け札が最も少なくなるメルドの組み方を選ぶ）で、**アンダーカットされる確率**と**期待得点**を求めます。
3. 探索を使わない設定（`search: 0`）では、アンダーカット確率 ≤ 18% かつ期待得点 ≥ 0 ならノックします。山札が残り8枚以下ならノックを優先します（期待得点 > −5 でノック）。デッドウッド0（ジン）なら必ずノックします。

## 7. 探索層（v2）

### 7.1 世界のサンプリング

1つの「世界」は、相手の手札10枚（6章と同じ方法でサンプリング）と、残りの未知カードをランダムに並べた山札です。各候補手を**同じ世界の集合**で評価するので、運の違いが比較に混ざりにくくなります。

**行動フィルタ（最強で使用。`oppFilter: 1`）**：相手の手札の候補を4つ作り、相手の直前の行動をどれだけ自然に説明できるかで重み付けして、1つを選びます。

- 直前に捨てた札：その手札なら、捨てた札はデッドウッド最小の選択からどれだけ外れているか → exp(−0.4×差)
- 直前に見送った捨て札：その手札なら、取ればデッドウッドが2点を超えて減ったはずか → exp(−0.3×(減少−2))
- ノックしていないこと：その手札ならノックできたはずの場合 → ×0.5（デッドウッド0なら×0.25）

**相手の打ち方のシミュレーション（オプション。`oppSim: 1`）**：7.2で相手の捨て札を決める方法を、次のように変えられます。

- デッドウッドが最小に近い候補（+2点以内）の中から選ぶ
- 自分の手札とつながっている札は手元に残す（つながり1つにつき0.5点の減点）
- こちらが拾って持っている札（相手からも見えている）に関係する札は捨てない（1つにつき4点の減点）

実際の最強AIの捨て札と一致する割合は、今の方法の62%から67%に上がりましたが、対戦では効果がなかったため既定では無効です。

### 7.2 捨て札・ノックの決定（`searchDiscard`）

候補手は、ヒューリスティック評価の上位4つの捨て札と、ノックできる捨て札すべてです。各世界で次のように値（自分から見た期待得点）を出し、平均が最大の手を選びます。

- **ノックする手**：その世界の相手手札に対して実際に得点計算した値。
- **ノックしない手**：相手の手番を1回シミュレーションします（相手は「捨て札で手が2点以上良くなるなら取る、そうでなければ山札から引く」「デッドウッド最小になる札を捨てる」「デッドウッド10以下になったらすぐノック」）。
  - 相手がノックしたら、付け札込みの実際の得点（マイナス）。
  - 山札が尽きたら0。
  - それ以外は、自分の次の手番開始時点の局面を**局面評価モデル**（7.4）で数値化。相手が捨てた札を自分が拾える場合は、その改善も評価に反映します。

ノックするかどうかは、「今ノックした場合の期待得点」と「続けた場合の局面評価」の直接比較になります。v1のアンダーカット確率のしきい値より柔軟な判断ができます。

### 7.3 引く場所の決定（`searchDraw`）

「捨て札を取る」と「山札から引く」を同じ世界の集合で比較します。

- 捨て札を取った後や、各世界で山札から引いたカードの後に、何を捨てるか（ノックするか）はヒューリスティック層の方策で決め、その後は7.2と同じく相手の手番をシミュレーションして評価します。
- 引いたカードごとの方策の結果はキャッシュし、同じカードを何度も計算しないようにしています。

### 7.4 局面評価モデル（`web/js/value.js`）

「自分が引く直前の局面から、このハンドで最終的に何点得る（失う）か」の期待値を予測する式です。

- 入力：自分の手札のヒューリスティック評価値 e（2章）、相手のデッドウッド o、山札の枚数 s
- 形：(e/20, o/20, s/10) の4次までの多項式と、e≤10・o≤10・e≤0 の指示変数（38個の係数）
- 学習：AI同士の自己対戦（約1万ハンド、約19万局面）で、各局面の実際の得点を目的変数として最小二乗法で当てはめ。データ生成は `tools/gen_value.mjs`、当てはめは `tools/fit_value.py`。
- 現在の係数は、探索版AI自身の対局から学習した第2世代です。

### 7.5 時間制限

- 1回の探索は最低60世界、最大4,000世界です。170msを超えたら打ち切ります（`timeBudget`）。
- 画面側はAIをWeb Workerで動かし、1アクションあたり「思考時間」と「240ms」の長い方だけ待ちます。AIの1ターン（引く＋捨てる）は約0.5秒です。
- 実測（Chromium、ヘッドレス）：思考時間の中央値は約80〜95ms、最大171ms。

## 8. ISMCTS（オプション。既定では無効）

`web/js/ismcts.js` に Single-Observer ISMCTS（Information Set MCTS）を実装しています。`mcts: 1` で有効になりますが、7章の探索より強くならなかったため、既定では使っていません（[history.md](history.md) 12章）。

- 繰り返しごとに7.1と同じ方法で世界を1つ引き、自分から見える情報で区別した1本の木をたどります。
- 自分が山札から引いた手は、引いたカードごとに枝分かれします（自分には見えるため）。相手が山札から引いた手は枝分かれしません（見えないため）。
- 相手の手は世界ごとに合法手が変わるので、UCTの式で「選べた回数」（availability）を使います。
- 候補手は、ヒューリスティックで絞った上位3つの捨て札とノックです（ルートでは7.2と同じ候補）。
- 木の末端は、自分の次の手番まで貪欲方策で進めてから局面評価モデルで採点します。最後まで打つプレイアウトはしません。
- 相手の手番は、UCTで選ぶ方式（`mctsOppGreedy: 0`）と、貪欲方策に固定する方式（`1`）を選べます。
- 0.2秒で約7,500回の繰り返しができます（Node.js）。

## 9. マッチ勝率を考えた判断（オプション。既定では無効）

勝敗は100点先取で決まるので、「何点取れるか」ではなく「マッチに勝つ確率がどう変わるか」で手を比べる仕組みです（`matchAware: 1`）。マッチ勝率で比べて強くならなかったため、既定では使っていません（[history.md](history.md) 13章）。

- **ハンド結果の分布**（`web/js/hand-outcomes.js`）：最強同士の6,000ハンドから、ディーラー／非ディーラーが何点で勝ったか、流局の割合を数えたもの（`tools/gen_outcomes.mjs`）。
- **マッチエクイティ表**（`web/js/match-equity.js`）：「自分 a 点・相手 b 点・次にどちらが配るか」からマッチに勝つ確率を、上の分布を使った動的計画法で計算します。バックギャモンのマッチエクイティ表と同じ考え方です。目標点ごとに初回だけ計算します（100点で数ms）。例：0対0で約50%、90対50で約75%、95対0で約92%。
- **効用**：7章の探索で得点を比べている部分を、「その結果になった後のマッチ勝率」に置き換えます。
  - ノックや相手のノックなど、得点が確定する結果は表から直接引きます。
  - 局面評価モデルの値（期待得点）は、そのまま表に入れると勝ち負けのばらつきが無視されます。そこで、「流局・勝ち・負けが通常の分布で起こり、期待得点がその値になる」と見なして、勝率の期待値に変換します。
- 画面からAIに渡す情報に現在のスコアと目標点（`view.match`）を加えました。

## 10. ニューラルネットの局面評価（オプション。既定では無効）

7.4の多項式モデルの代わりに、カードそのものを入力にする小さなニューラルネットで局面を評価する仕組みです（`nn: 1`）。予測精度は上がりましたが、対戦では強くならなかったため、既定では使っていません（[history.md](history.md) 14章）。

- **入力（212個）**：自分の手札・相手の手札・捨て札の山・一番上の捨て札（それぞれ52枚分の0/1）、山札の枚数、自分の評価値、両者のデッドウッド
- **形**：212 → 64 → 32 → 1 の全結合（ReLU）。出力×25がハンドの期待得点
- **学習**（`tools/train_nn.py`、numpyのみ）
  - Adamで最小二乗法
  - スート（♠♥♦♣）の入れ替えに対して対称なゲームなので、ミニバッチごとにスートをランダムに入れ替えてデータを増やす
  - 検証用データはデータの末尾10%（同じハンドの局面が学習側と検証側に分かれないようにするため）
  - データ生成は `tools/gen_nn.mjs`
  - 現在の重みは、「ふつう」同士の約159万局面で事前学習し、最強同士の約157万局面で追加学習したもの
- **推論**（`web/js/nn.js`）
  - 外部ライブラリなし
  - 1層目は、0/1の入力に対応する重みの行を足し合わせるだけで計算できる
  - 1回の評価は数マイクロ秒

## 11. 各レベル

| レベル | 中身 |
| --- | --- |
| **最強** | この文書の全機能（ヒューリスティック層＋探索層） |
| **ふつう** | 初版の最強AI（v1）と同じ考え方。ヒューリスティック層だけで判断します（`search: 0`, `knockChoice: 0`）。ノック判断は6章のしきい値を使います |
| **よわい** | デッドウッド最小化だけを見る貪欲AI。捨て札で2点以上良くなるなら取り、デッドウッドが最小になる札を捨て、ノックできればすぐノックします |
