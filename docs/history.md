# AI 開発の試行記録

自己対戦スクリプト [`tools/selfplay.mjs`](../tools/selfplay.mjs) で計測しました。各配札を**席を入れ替えて2回**対戦させ、運の偏りを減らしています（「N ハンド」は入れ替え後の合計数）。指標は **A側の1ハンドあたり平均得点差**（＋ならA有利）です。

> 1ハンドの得点のばらつきは大きいため、1,000〜3,000ハンドでもおおむね ±0.5〜0.8 点程度の誤差があります。差が1点未満のものは「差なし」とみなしています。

## 1. 初期版ヒューリスティックAI

初期パラメータ: `alpha 1.6`, `alphaDecayStock 10`, `beta 7`

| 対戦 | ハンド数 | 平均得点差 |
| --- | --- | --- |
| 最強 vs ふつう | 600 | +1.85 |

勝ったハンド数では負け越し（255 対 342）。ノックが慎重なぶん勝ち数は少ないが、1回の勝ちで大きく稼ぐ形でした。

## 2. パラメータ探索（対「ふつう」）

### 600 ハンド（seed 2）

| A側の変更 | 平均得点差 |
| --- | --- |
| 必ず即ノック | +1.71 |
| `undercutMax 0.3` | +2.22 |
| `beta 0`（危険度を無視） | **+0.07** |
| `alpha 0.8` | +3.37 |
| `alpha 2.5` | −0.10 |

→ **危険度（捨て札の安全性）がとても重要**。ドロー期待値の重みは初期値が大きすぎました。

### 2,000 ハンド（seed 3）

| A側の変更 | 平均得点差 |
| --- | --- |
| 初期値のまま | +2.15 |
| `alpha 0.5` | +2.91 |
| `alpha 0.8` | +2.63 |
| `alpha 1.1` | +2.69 |
| `alpha 0.8, beta 11` | +1.87 |
| `alpha 0.8, beta 4` | +3.23 |
| `alpha 0.8, undercutMax 0.3` | +2.45 |
| `alpha 0.8, knockBonus 0, ginBonus 0` | +2.77 |

### 3,000 ハンド（seed 4）

| A側の変更 | 平均得点差 |
| --- | --- |
| `alpha 0.8, beta 4` | +3.71 |
| `alpha 1.2, beta 4, alphaDecayStock 25` | **+3.73**（採用） |
| `alpha 1.5, beta 4, alphaDecayStock 32` | +3.61 |
| `alpha 0.8, beta 2` | +3.38 |

→ このあたりで頭打ち。`alpha 1.2, beta 4, alphaDecayStock 25` を採用しました。

## 3. モンテカルロ法（プレイアウト）版 — 不採用

各候補手について、相手の手札と山札の順番をサンプリングし（ノック判断と同じ「上達させた」相手手札）、両者を貪欲方策で最後までプレイして得点の平均を比べる方式を試しました（100サンプル、候補4手）。

| 対戦 | ハンド数 | 平均得点差 |
| --- | --- | --- |
| MC版 vs ふつう | 1,000 | +4.02（同じ条件で 最強 vs ふつう は +4.61） |
| MC版 vs 最強 | 1,000 | −1.85 |
| MC版（ノック判断だけヒューリスティック）vs 最強 | 1,000 | −2.17 |
| 同上・候補2手 | 1,000 | −2.46 |

→ プレイアウトの方策（すぐノックする貪欲AI）が実際の打ち方と違うため評価が偏り、ヒューリスティック版より弱くなりました。プレイアウトに最強AI自体を使えば改善の余地はありますが、1手あたり数秒以上かかり、ブラウザで動かすには重すぎるため見送りました。

## 4. 最強同士の直接対決での調整

基準の最強AI（B）と、1点だけ変えたAI（A）の対戦。2,000 ハンドずつ。

| A側の変更 | 平均得点差 | 判断 |
| --- | --- | --- |
| 必ず即ノック（シミュレーションなし） | **−1.69** | ノック判断のシミュレーションは有効 |
| ジン狙い（デッドウッド5超ではノックしない） | **−1.50** | ジン狙いは損 |
| `undercutMax 0.1` | +0.13 | 差なし |
| `undercutMax 0.3` | −0.45 | 差なし |
| `takeMargin 1` | +0.19 | 差なし |
| `takeMargin −1` | −0.48 | 差なし |
| `beta 6` | −0.08 | 差なし |
| `alpha 0.8` | −0.04 | 差なし |
| `topK 6` | −0.00 | 差なし |
| `knockBonus 8` | −0.63 | 差なし |
| `ginBonus 15` | +0.23 | 差なし |
| ノック判断のサンプル数 150 | −0.09 | 差なし |

→ 現在の値がほぼ最適付近。

## 5. 捨て札の2手読み（`deepK`）— 不採用

上位の捨て札候補について、「次のドローで最善を尽くした後の評価」の期待値まで読む方式。

| A側の変更 | ハンド数 | 平均得点差 |
| --- | --- | --- |
| `deepK 3` | 1,400 | −0.27 |
| `deepK 3`（別seed） | 1,400 | +0.60 |
| `deepK 5` | 1,400 | +0.06 |

→ 有意な改善なし。計算が重くなるだけなので無効（`deepK 0`）のままにしました。

| 最強 vs ふつう | 3,000 | 約 +3.7（別seedで +4.6） |

比較相手は自作のAIのみで、人間の上級者や他のジンラミーAIとは比べていません。

## 今後のアイデア

- 相手のノックが近いと判断したら、高い札を早めに処分する（守りの強化）
- 相手手札の推定を、実際の打ち方から学習したモデルに置き換える
- Web Worker で計算を裏に回し、プレイアウト型やより深い探索を試す
